# Совместная разработка 1С

Да, 1С поддерживает совместную разработку и контроль версий.

Для установленной учебной версии 8.3.27.1688 встроенное хранилище конфигурации недоступно. В этом комплекте используется выгрузка Конфигуратора в XML/BSL и Git. Если требуется работа без ручной выгрузки, см. [Автоматизация.md](Автоматизация.md): переход на EDT требует отдельной проверки совместимости и импорта проекта.

## Выбор инструмента

**Встроенное хранилище Конфигуратора:** администратор создает хранилище и пользователей. Каждый участник подключает свою локальную базу, захватывает нужные объекты, изменяет их и помещает обратно с комментарием. Остальные получают новые версии. На один объект действует один захват. Используйте доступный сетевой ресурс или сервер хранилища, предварительно проверив доступность механизма в используемой редакции платформы.

**EDT + Git:** EDT хранит проект в файлах и поддерживает ветки, коммиты и слияния Git. Создайте проект EDT импортом конфигурации из базы или CF, затем общий удаленный Git-репозиторий. Каждый клонирует проект и подключает собственную базу. Все используют согласованные совместимые версии EDT и платформы. Поставляемый каталог src имеет формат Конфигуратора, его нельзя просто объявить готовым проектом EDT.

**Конфигуратор + XML/BSL + Git:** подходит для старта на уже установленной платформе. Изменяйте свою базу, выгружайте конфигурацию в src, фиксируйте изменения Git. После получения общей версии загружайте src в базу. Экспорт всей базы в DT не заменяет текстовые исходники.

## Начало для команды

1. Каждый участник клонирует [huksleva/cinema](https://github.com/huksleva/cinema). Доступ для отправки веток выдает владелец репозитория.
2. Перейдите в папку `Кинотеатр` внутри клона и создайте отдельную базу разработки из `src`. Порядок сборки описан в [корневом README](../../README.md#запуск-из-исходников).
3. На всех компьютерах используется одна сборка платформы. Исходная проверенная сборка — учебная 8.3.27.1688. Совместимость EDT с этой учебной сборкой отдельно не проверялась.
4. Договоритесь о владельцах объектов и интеграторе. Для учебной версии выполняйте запуски одной базы последовательно.

## Одна задача

Получить main и создать ветку:

```powershell
git switch main
git pull --ff-only
git switch -c feature/income-document
```

В Конфигураторе загрузить общую конфигурацию из src в свою базу и обновить конфигурацию базы данных. Выполнить задачу, проверить ее, выгрузить конфигурацию из своей базы в src. Меню: Конфигурация → Выгрузить конфигурацию в файлы.

```powershell
git status
git diff --stat
git diff
git add src/Documents/Приход.xml src/Documents/Приход docs
git commit -m "Добавлен приход товаров и описание проверки"
git push -u origin feature/income-document
```

Имена путей и сообщение в примере меняются под фактическую задачу. `git add` должен включать только намеренные изменения. После отправки ветки создают запрос на слияние, другой участник проверяет код, затем интегратор проверяет объединенную конфигурацию в 1С.

## Что нельзя сливать как исходный код

- `1Cv8.1CD` — данные и конфигурация в файле базы, текстовое слияние неприменимо.
- `.dt` — резервная копия, ее используют для переноса и восстановления.
- `.cf` — бинарная конфигурация, ее хранят как артефакт выпуска.

Конфликты XML форм и метаданных требуют внимательной проверки UUID и структуры, затем загрузки и проверки в 1С. Отсутствие конфликта Git само по себе не гарантирует работоспособности. Исходники EDT и выгрузка Конфигуратора имеют разные форматы. Выберите один формат как основной.

## Учет вклада

Задача может завершаться кодом, тестом, инструкцией, дизайном или докладом. Фиксируйте автора задачи, критерии приемки и результат проверки. Число коммитов и строк кода не равно полезности. Не подписывайте автоматически созданный код именами студентов, которые его не проверяли и не дорабатывали.
