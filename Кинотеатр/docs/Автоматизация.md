# Автоматизация разработки 1С и Git

## Можно ли обойтись без ручной выгрузки и загрузки

Да, такой рабочий процесс возможен. Для этого используют среду **1C:Enterprise Development Tools (EDT)** либо дополнительную локальную автоматизацию пакетных команд Конфигуратора. GitHub хранит полученные файлы и историю изменений; преобразование между конфигурацией 1С и файлами выполняют локальные инструменты разработки.

## Вариант с EDT

В EDT разработчик редактирует объекты конфигурации как файловый проект. Эти файлы непосредственно отслеживаются Git. Отдельно выгружать их из Конфигуратора перед каждым коммитом не требуется. EDT связывает проект с локальной информационной базой и поддерживает автоматическое обновление базы перед запуском приложения.

Начальная настройка состоит из установки совместимой EDT, импорта конфигурации в проект, подключения локальной базы и согласования файлового формата с командой. После этого разработчик работает в EDT, а коммиты и отправку изменений выполняет через средства Git.

Автоматизация экспорта и обновления базы не устраняет необходимость выбирать изменения для коммита, разрешать конфликты и проверять объединенную конфигурацию.

**Для учебной 1С 8.3.27.1688 совместимость с конкретной версией EDT в этой среде не проверена.** В официальном описании EDT 2025.1 указан минимальный номер обычной платформы 8.3.27.1606. Само по себе соответствие номера сборки этому требованию не подтверждает поддержку учебного дистрибутива. Устанавливать произвольную последнюю EDT без проверки совместимости не следует.

## Вариант с обычным Конфигуратором

В проекте уже есть пакетные сценарии:

- `scripts/Export.ps1` выгружает конфигурацию выбранной базы в `src`;
- `scripts/Build.ps1` загружает `src` в отдельную базу `build/infobase`, обновляет ее структуру и проверяет конфигурацию;
- `scripts/Test.ps1` выполняет проверки в этой отдельной базе.

Их можно включить в согласованный локальный процесс, например запускать экспорт перед коммитом и сборку после получения общей версии. Однако готовые Git-хуки, фоновое наблюдение за базой и автоматические коммиты в этом комплекте **не установлены**. Build.ps1 работает с отдельной базой сборки, а не синхронизирует открытую рабочую базу разработчика.

Учебная платформа ограничивает число сеансов одной базы. Пакетная команда Конфигуратора не должна запускаться одновременно с другим сеансом этой же базы. Поэтому постоянная синхронизация открытой учебной базы потребует отдельного согласования порядка закрытия сеансов и обработки ошибок.

## Что нельзя заменить синхронизацией Git

Файл `1Cv8.1CD` содержит базу в бинарном формате. Git не объединяет товарные записи и документы нескольких копий этой базы. Для командной разработки синхронизируют исходники конфигурации, а данные передают через резервную копию DT либо согласованные механизмы обмена данными.
